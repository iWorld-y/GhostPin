# task-storage Specification

## Purpose

定义 GhostPin 任务真源的版本化存储与升级规则，将分组、整数 ID 和下一编号作为一致的数据状态保存，并保证 App、CLI 和提醒服务的多进程写入不会丢失已提交的任务或元数据。

## Requirements

### Requirement: 版本化任务文档

任务文件 SHALL 使用包含 `schemaVersion`、`nextID` 和 `items` 的 JSON 对象，新版本的 `schemaVersion` MUST 为 `2`。`items` 中每条任务 MUST 具有唯一整数 `id` 和非空字符串 `group`；`nextID` MUST 不小于 `10000` 且大于全部现存 ID，日期继续使用 ISO 8601。

#### Scenario: 保存新版本任务文件

- **WHEN** 空任务库在 `默认` 中首次成功新增任务
- **THEN** 文件包含 `schemaVersion: 2`、`nextID: 10001`，且 `items` 包含 `id: 10000`、`group: "默认"` 的任务

#### Scenario: 初次读取没有任务文件

- **WHEN** 任务文件不存在且没有可迁移的旧数据
- **THEN** 系统返回空任务集合，下一编号为 `10000`，不因普通查询创建任务文件

### Requirement: 分组与 ID 一次迁移

系统 SHALL 识别旧 UUID 任务数组，在首次成功的数据访问中一次性生成稳定整数 ID、为全部旧任务设置 `group: "默认"`，并将 `nextID` 设为 `10000` 加旧任务数量。迁移 MUST 保留任务标题、状态、创建时间、完成时间、提醒时间、已发送提醒时间、优先级、截止时间和描述，继续支持既有缺省字段兼容。

#### Scenario: 同时升级未完成和已完成任务

- **WHEN** 旧数组中存在三条不同状态的任务
- **THEN** 成功迁移后仍有三条任务，ID 按稳定顺序从 `10000` 分配、组别均为 `默认`，下一编号为 `10003`

#### Scenario: 迁移后立即新增任务

- **WHEN** 成功迁移两条历史任务后，新增一条显式指定组别的任务
- **THEN** 历史任务保持 `10000` 和 `10001`，新任务获得 `10002`

#### Scenario: 重复访问新格式

- **WHEN** 文件已经是有效的新版本文档
- **THEN** 系统直接使用已保存的 ID、组别和下一编号，不再次执行历史归组或编号

### Requirement: 原始备份与迁移失败保护

替换旧任务文件前，系统 MUST 成功保留原文件的逐字节备份。已有备份 MUST 不被覆盖；内容相同的备份可复用，内容不同必须报告冲突并停止。备份或最终提交失败时，旧任务文件 MUST 保持不变，系统不得发布已迁移成功的状态。

#### Scenario: 首次升级保留备份

- **WHEN** 系统成功将旧数组升级为新版本文档
- **THEN** 旧文件的完整原始内容仍保存在备份中，新文件只在迁移全部完成后可见

#### Scenario: 备份完成后提交失败

- **WHEN** 原始备份已经保存，但新任务文档提交失败
- **THEN** 原任务文件保持原样，备份可供核对，下次重试仍得到相同的历史编号

#### Scenario: 已存在不匹配备份

- **WHEN** 原始备份已存在且内容与本次待迁移文件不同
- **THEN** 系统报告冲突，不覆盖备份或任务文件

### Requirement: 全部写入口保持一致性

新增、字段修改、换组、状态推进、删除、提醒发送记录及迁移 SHALL 共同遵守进程间串行写入规则。每次写入 MUST 以锁内重新读取的最新任务文档为基础，原子提交任务集合与下一编号；成功提交前 MUST 不发布新的内存任务状态。

#### Scenario: App 旧快照与 CLI 新增并发

- **WHEN** App 持有旧任务快照，CLI 成功新增任务后 App 推进另一条任务的状态
- **THEN** CLI 新增的任务仍保留，目标状态更新成功，下一编号不回退

#### Scenario: 提醒回写与换组并发

- **WHEN** Agent 已成功将任务换组，提醒服务随后记录同一任务的已发送时间
- **THEN** 最新组别和已发送提醒时间同时保留

#### Scenario: 已删除任务的过期状态请求

- **WHEN** App 持有的任务已被 CLI 删除，App 随后尝试推进该任务状态
- **THEN** 操作不得恢复已删除任务或覆盖其他任务，任务文件保持最新有效状态

### Requirement: 无效文档不得重置

未知存储版本、重复或非法 ID、空组别、非法下一编号及损坏内容 MUST 导致加载或写入失败，系统 MUST 报告可诊断错误，不得以空库覆盖原文件或根据现存任务重置下一编号。App 已有有效快照时 MUST 保留该快照。

#### Scenario: 下一编号小于现存 ID

- **WHEN** 文档的 `nextID` 不大于某条现存任务 ID
- **THEN** 系统拒绝文档，不自动修复计数器，不执行后续新增

#### Scenario: 外部文件暂时损坏

- **WHEN** App 已加载有效任务后，外部文件变为无效文档
- **THEN** App 保留最后一次成功加载的任务，原文件不被覆盖，并报告错误

### Requirement: 失败命令不触发迁移

CLI 的帮助和参数错误 MUST 不访问或迁移任务文件。业务目标不存在等失败操作 MUST 不提交迁移、变更任务或消耗编号；成功查询旧数据时允许执行一次完整迁移。

#### Scenario: 旧任务文件存在但新增缺少组别

- **WHEN** 调用方未提供必填组别而执行新增
- **THEN** 命令失败，旧文件及备份状态保持不变

#### Scenario: 对旧任务库操作不存在的数字 ID

- **WHEN** 根据稳定迁移映射仍找不到指定数字 ID
- **THEN** 命令报错，不写入新格式或备份，不消耗编号
