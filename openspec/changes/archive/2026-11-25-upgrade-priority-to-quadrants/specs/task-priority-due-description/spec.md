# Spec Delta

## ADDED Requirements

### Requirement: 重要度与紧迫度字段

任务 SHALL 使用两个正交布尔维度表达原生四象限优先级：`important`（重要度：`true` 为重要，`false` 为一般）与 `urgent`（紧迫度：`true` 为紧急，`false` 为不紧急）。新创建任务 MUST 显式指定 `important` 与 `urgent`，不得通过隐式默认值静默落入「一般 · 不紧急」。

有效紧急程度 MUST 由存储值与截止日期共同推导：当 `urgent` 为 `true`，或 `dueAt` 非空且早于当前本地日历次日零点（即已逾期或本地当天到期）时，有效紧急程度为紧急；其余情况为不紧急。截止日期触发的有效紧急升级 MUST 仅作用于投影与展示，不得改写持久化字段 `urgent`。

#### Scenario: 显式创建重要但不紧急任务

- **WHEN** 创建任务时指定 `important: true`、`urgent: false` 且未设置 `dueAt`
- **THEN** 该任务持久化保存 `important: true` 与 `urgent: false`，有效象限为「重要 · 不紧急」

#### Scenario: 无截止日期的紧急任务

- **WHEN** 创建任务时指定 `important: false`、`urgent: true` 且 `dueAt` 为空
- **THEN** 该任务有效象限为「一般 · 紧急」，无需设置伪造的截止日期

#### Scenario: 截止日期自动触发紧急升级而不改写原值

- **WHEN** 一条 `important: true`、`urgent: false` 且 `dueAt` 为本地当天 18:00 的任务被投影展示
- **THEN** 其有效象限为「重要 · 紧急」，而存储中的 `urgent` 仍保持 `false`；当 `dueAt` 清除或延后至明天以后时，有效象限自动恢复为「重要 · 不紧急」

### Requirement: 四象限投影排序规则

未完成任务 SHALL 按以下顺序排序：同状态（Doing 在 Todo 之前）内按有效象限优先级降序排列——依次为「重要 · 紧急（Q1）」→「重要 · 不紧急（Q2）」→「一般 · 紧急（Q3）」→「一般 · 不紧急（Q4）」；同一有效象限内按截止日期 `dueAt` 升序（快到期及更早逾期者在前），无截止日期者排在同象限有截止日期任务之后、按创建时间倒序（同创建时间按 ID 降序）。已逾期任务 MUST 不再全局沉底，而是依据其有效紧急状态参与所在象限（Q1 或 Q3）排序。

#### Scenario: 四象限线性投影顺序

- **WHEN** 同一状态下存在有效象限分别为 Q1、Q2、Q3、Q4 的四条未完成任务
- **THEN** 排序结果严格为 Q1 → Q2 → Q3 → Q4

#### Scenario: 已逾期任务不再沉底

- **WHEN** 存在一条已逾期的「重要（`important: true, urgent: false`）」任务与一条未逾期的「重要 · 不紧急」任务
- **THEN** 已逾期任务因有效紧急进入 Q1，排在未逾期的 Q2 任务之前

#### Scenario: 同象限内截止日期与创建时间次序

- **WHEN** 同一有效象限内存在两条有截止日期的任务（分别今天 14:00 与今天 18:00）和一条无截止日期的任务
- **THEN** 排序依次为今天 14:00 → 今天 18:00 → 无截止日期任务

## MODIFIED Requirements

### Requirement: 截止日期字段

任务 SHALL 支持可选截止日期 `dueAt`，具体到日期与时刻；与提醒时间 `reminderAt` 及紧迫度 `urgent` 相互独立，可单独设置且不强制校验与提醒时间的先后（语义上提醒应早于截止）。当 `dueAt` 已逾期或位于本地当天内时，投影层 SHALL 将该任务的有效紧急程度视为紧急。

#### Scenario: 设置截止日期

- **WHEN** 创建任务时指定截止日期为某具体时刻
- **THEN** 该任务的截止日期为该时刻，并被持久化

#### Scenario: 无截止日期

- **WHEN** 创建任务时未指定截止日期
- **THEN** 该任务无截止日期，值为空，有效紧急程度仅由 `urgent` 决定

### Requirement: HUD 视觉标记

HUD SHALL 展示有效象限标记以区分四档——依次为「急重」（重要 · 紧急）、「重要」（重要 · 不紧急）、「紧急」（一般 · 紧急）、「稍后」（一般 · 不紧急），并在其右侧展示组别标记；两个标记 MUST 位于任务标题行右侧，作为整体与卡片右侧内容边界对齐。组名文本区域 MUST 不超过同字体三个汉字的宽度，保持单行，超出时尾部省略且省略号计入上限；展示限制 MUST 不改变存储组名或限制组名长度。过期任务 SHALL 使用删除线标注，描述 SHALL 以较小字体展示。时间行 MUST 只展示截止日期 `dueAt`，为空时不显示时间；过期截止时间 MUST 使用与标题删除线相同的红色超时语义。HUD SHALL NOT 展示创建时间或提醒时间。

#### Scenario: 优先级标记

- **WHEN** HUD 展示有效象限分别为 Q1、Q2、Q3、Q4 的任务
- **THEN** HUD 分别以可辨识的四档有效象限标记「急重」「重要」「紧急」「稍后」加以区分，组别标记不改变其视觉语义

#### Scenario: 过期删除线

- **WHEN** 一条任务已过期且未完成
- **THEN** HUD 以删除线标注该任务标题

#### Scenario: 描述小字体

- **WHEN** 一条任务具有描述文本
- **THEN** HUD 以小于标题的字体展示该描述

#### Scenario: 有截止日期时显示截止时间

- **WHEN** 一条任务具有截止日期
- **THEN** HUD 以日期与时刻格式展示该截止日期，不展示创建时间与提醒时间

#### Scenario: 无截止日期时不显示时间

- **WHEN** 一条任务没有截止日期
- **THEN** HUD 不显示任何时间

#### Scenario: 过期截止时间变红

- **WHEN** 一条任务已过期且未完成
- **THEN** HUD 以红色展示该任务的截止时间

#### Scenario: 优先级和组别标记整体右对齐

- **WHEN** HUD 展示一条属于 `默认` 组的 Q1（重要 · 紧急）任务
- **THEN** 标题行从左到右依次为任务标题、有效象限标记「急重」、组别标记，两个标记作为整体靠卡片右侧对齐，组别标记显示 `默认`

#### Scenario: 标题长度变化

- **WHEN** 列表同时包含短标题和会换行的长标题，或用户调整 HUD 宽度
- **THEN** 两个标记保持在各卡片标题行右侧，组别标记右边缘与卡片右侧内容边界对齐，不随标题长度漂移，也不与标题重叠

#### Scenario: 长组名按显示宽度省略

- **WHEN** 任务的完整组名超过同字体三个汉字的显示宽度
- **THEN** 组别标记在限定宽度内单行尾部省略，省略号也在宽度内，任务存储和 CLI 查询仍使用完整组名

#### Scenario: 默认组不隐藏

- **WHEN** 迁移后的历史任务属于 `默认`
- **THEN** HUD 同样展示 `默认` 组别标记，不因属于内置组而省略该标记

## REMOVED Requirements

### Requirement: 优先级字段

**Reason**: 一维三档线性优先级（高/中/低，默认中）无法无损映射到四象限视图，且默认值导致大量未评估任务塌陷到「一般 · 不紧急」。
**Migration**: 替换为「重要度与紧迫度字段」（`important` 与 `urgent` 两个正交布尔维度）；历史 v2/v1 数据在迁移时将 `high` 映射为 `important: true`，`medium`/`low`/缺省映射为 `important: false`，`urgent` 初始为 `false`。

### Requirement: 任务排序规则

**Reason**: 原有按线性优先级排序且将已逾期任务全局沉底的规则与四象限视图（已逾期=紧急）语义冲突。
**Migration**: 替换为「四象限投影排序规则」：同状态内按有效象限 `Q1 → Q2 → Q3 → Q4` 排序，同象限内按 `dueAt` 升序与创建时间倒序，已逾期任务进入所在紧急象限（Q1/Q3）不再沉底。
