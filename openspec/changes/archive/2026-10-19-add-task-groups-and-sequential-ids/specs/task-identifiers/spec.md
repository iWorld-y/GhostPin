# Spec Delta

## Purpose

定义 GhostPin 本地任务库中从 10000 开始递增的整数 ID，使 Agent 能用较短的标识查询和修改任务，并约束历史任务编号、跨组唯一性及删除、重启和并发写入后的编号稳定性。

## ADDED Requirements

### Requirement: 本地任务库统一整数 ID

任务 ID SHALL 是不小于 `10000` 的整数，在整个本地任务库内唯一。全部分组和任务状态 MUST 共用一个编号序列；ID MUST 在任务存续期间保持不变。

#### Scenario: 不同组连续新增

- **WHEN** 空任务库依次在 `默认` 和 `GhostPin` 中成功新增任务
- **THEN** 两条任务分别获得 `10000` 和 `10001`，不因组别重新计数

#### Scenario: 完成或移动任务

- **WHEN** 一条任务被完成、重开或移入另一组
- **THEN** 任务 ID 保持不变，编号序列不会因这些操作重新分配

### Requirement: 持久化下一编号

系统 SHALL 将下一可分配 ID 与任务集合一起持久化。空任务库的初始下一编号 MUST 为 `10000`；每次成功新增 MUST 使用当前下一编号并将其递增一次，普通读取 MUST 不消耗编号。

#### Scenario: 重启后继续编号

- **WHEN** 已成功创建 `10000` 和 `10001`，应用或 CLI 重启后再次新增任务
- **THEN** 新任务获得 `10002`

#### Scenario: 读取任务列表

- **WHEN** 调用方重复查询列表且没有新增任务
- **THEN** 下一编号保持不变

### Requirement: 删除后不复用编号

删除任何任务 MUST 不降低下一编号。即使删除最大 ID 的任务或删除全部任务，后续新增也 MUST 继续使用已持久化的下一编号，不得依据剩余任务重新从 `10000` 或最大现存 ID 计数。

#### Scenario: 删除最大编号任务

- **WHEN** 已分配至 `10002`，删除 ID `10002` 后再新增任务
- **THEN** 新任务获得 `10003`，不会复用 `10002`

#### Scenario: 删除全部任务

- **WHEN** 已分配过 `10000` 和 `10001`，随后删除全部任务并重启
- **THEN** 下一条新任务获得 `10002`

### Requirement: 历史任务稳定编号

旧 UUID 任务 SHALL 按 `createdAt` 升序从 `10000` 起编号，时间相同时按规范化为小写的 UUID 字符串字典序升序确定顺序，所有状态均参与编号。迁移后的任务 MUST 保持已分配 ID，重新加载或重复启动 MUST 不重新编号。

#### Scenario: 历史任务创建时间不同

- **WHEN** 待迁移旧任务包括较早创建的 Done 和较晚创建的 Todo
- **THEN** Done 取得较小的新 ID，Todo 取得较大的新 ID，两条任务的状态和时间保持不变

#### Scenario: 历史任务创建时间相同

- **WHEN** 多条旧任务的创建时间相同，输入数组顺序不同
- **THEN** 按 UUID 排序确定的 UUID 与整数 ID 对应关系一致

#### Scenario: 重复打开升级后的任务库

- **WHEN** 任务库已经完成升级，再次由 App 或 CLI 加载
- **THEN** 全部 ID 和下一编号保持不变

### Requirement: 并发分配唯一编号

多个进程同时新增任务时，所有成功操作 MUST 获得不同的递增 ID，且成功新增的任务 MUST 全部保留。保存失败 MUST 不提交任务或推进持久化的下一编号。

#### Scenario: 两个 Agent 同时新增

- **WHEN** 两个 CLI 进程对初始下一编号为 `10000` 的同一任务库同时新增任务
- **THEN** 成功结果分别获得 `10000` 和 `10001`，任务文件同时包含两条任务且下一编号为 `10002`

#### Scenario: 新增保存失败

- **WHEN** 新增操作在提交任务文件前失败
- **THEN** 原任务集合和下一编号保持不变，下次成功新增使用原下一编号

### Requirement: 数字 ID 对外契约

CLI 的任务 ID 参数 SHALL 使用十进制整数，任务 JSON 的 `id` SHALL 输出为 JSON 整数。UUID、负数、小数和小于 `10000` 的值 MUST 被拒绝，不得通过 UUID 别名定位迁移后的任务。

#### Scenario: 使用数字 ID 操作

- **WHEN** 调用方请求完成已有任务 `10000`
- **THEN** 命令按整数 ID 精确定位并返回 `"id": 10000`

#### Scenario: 使用旧 UUID 操作

- **WHEN** 调用方将旧 UUID 作为任务 ID 传入
- **THEN** 命令报错并以非零退出码结束，任务数据保持不变
