## Context

动机与范围见 `proposal.md`。当前 `AppPreferences` 使用 `UserDefaults` 保存 HUD 配置，`AppState.toggleHUDMode()` 已统一处理模式切换，`WindowCoordinator` 负责窗口穿透和焦点行为；应用通过 `AppDelegate` 的启动与退出生命周期启动/停止服务。当前设置页是单一 `Form`，App target 未链接 Carbon，仓库正式规格仍要求默认不注册全局快捷键。

## Goals / Non-Goals

**Goals:**

- 保持默认行为不变：快捷键为空、开关关闭、应用不注册全局快捷键。
- 在高级设置中完成快捷键录制、校验、注册和错误反馈。
- 让托盘开关与全局快捷键复用同一套 HUD 模式切换链路。
- 在快捷键配置变更失败时保留原有可用配置，避免出现已保存但未生效的状态。
- 对 macOS 系统快捷键提供可解释的有限预检，并明确第三方冲突检测的边界。

**Non-Goals:**

- 不支持多个交互模式快捷键或其他功能快捷键。
- 不使用全局按键监控、事件 tap 或辅助功能权限扫描所有键盘事件。
- 不枚举 Raycast、Karabiner、Keyboard Maestro、skhd 等第三方工具的内部快捷键配置。
- 不改变托盘开关、HUD 任务状态、任务数据格式或 CLI 行为。

## Decisions

### 1. 快捷键配置属于 App 层

新增 `HotKeyShortcut` 作为 App 层的 Codable 值类型，保存物理 key code、Carbon modifier mask 和设置页显示名称；快捷键注册服务也放在 App 层。快捷键是 macOS 输入机制配置，不属于 `GhostPinCore` 的待办领域模型，避免让 Core 依赖 AppKit 或 Carbon。

### 2. 使用两个持久化字段表达启用状态

`AppPreferences` 增加：

- `hudModeHotKeyEnabled: Bool`，默认 `false`；
- `hudModeHotKeyShortcut: HotKeyShortcut?`，默认 `nil`。

关闭开关只注销快捷键，不清除 `hudModeHotKeyShortcut`。打开开关但快捷键为空时，设置页使用本地待配置状态；在有效快捷键注册成功前，不修改上述持久化字段。

### 3. 由 AppState 编排注册生命周期

新增单一职责的 `HotKeyService`，只管理一个交互模式快捷键及其回调：

- `AppState.start()` 在读取到“已启用且有配置”时尝试注册；默认关闭或快捷键为空时跳过注册。
- `AppState.stop()` 注销快捷键。
- 注册回调只回到主线程并调用已有 `toggleHUDMode()`，不在快捷键服务中直接操作窗口。
- 设置页启用、替换或恢复快捷键时由 `AppState` 负责事务编排，视图只提交用户录制的候选值。

这样托盘与快捷键都经过 `toggleHUDMode()`，保留现有 `WindowCoordinator.updateHUD()` 和 `applyHUDInteraction()` 的焦点策略。

### 4. 配置采用“先验证、后提交”

配置交互按以下顺序工作：

```text
用户打开开关
    ├─ 没有快捷键 → 待配置，不落盘、不注册
    └─ 已有快捷键 → 尝试预检与注册
                         ├─ 成功 → 保存快捷键和 enabled=true
                         └─ 失败 → 保持原配置和原启用状态
```

替换已经生效的快捷键时，应用保留旧配置作为回滚值；新候选值注册成功后再完成替换，失败则恢复旧注册。关闭开关时先停止注册，再保存 `enabled=false`，快捷键值继续保留。

启动时如果已保存配置但注册失败，不清除用户配置；AppState 保留运行时错误状态，设置页显示当前不可用原因，让用户可以重新录制或关闭开关。

### 5. 设置页使用 TabView 分离高级配置

现有 HUD 表单保留为主 Tab，新增“高级”Tab。高级 Tab 包含启用开关、当前快捷键显示、录制按钮和状态提示。录制按钮只在开关打开后可用；开关打开且没有快捷键时，页面明确显示“请录制快捷键”。

录制期间使用 `NSEvent` 的本地 key-down monitor，仅接收 GhostPin 自身设置窗口收到的事件；Escape 取消录制，普通不合规按键只显示校验错误，不改动已保存配置。录制完成后立即交给 AppState 验证和注册，不把 Carbon 注册逻辑放进 SwiftUI View。

### 6. 使用普通全局注册并进行有限预检

快捷键服务使用 Carbon 的普通非独占注册，避免 GhostPin 抢占其他软件的快捷键。注册前读取系统可查询的 symbolic hot keys，若候选组合与已知系统快捷键冲突则阻止保存；系统注册本身失败时同样阻止保存并回滚。

普通非独占注册不能证明第三方软件没有注册相同组合键，因此成功状态文案只能表达“GhostPin 已注册”，并附带第三方冲突无法完全检测的提示。不能把一次注册成功展示成“全局无冲突”。不使用 exclusive 注册作为探测手段，因为它会改变其他非独占注册的接收行为，而不只是进行只读检查。

### 7. 快捷键规则在录制入口统一校验

录制结果使用 physical key code 和修饰键生成候选值。必须包含 Command、Option、Control 或 Shift 中至少一个修饰键，或为 F1-F20 功能键；普通单字母、单数字和不合规按键直接拒绝。显示名称只用于设置页展示，注册与比较以 key code 和 modifier mask 为准。

## Risks / Trade-offs

- **第三方软件冲突无法完整检测** → 使用系统 symbolic hot key 预检、注册结果和明确的“可能存在第三方冲突”提示，不承诺识别占用者。
- **录制当前快捷键时可能误触发模式切换** → 进入录制状态时暂时注销当前快捷键；取消或候选值失败时恢复旧注册。
- **Carbon 使用物理 key code，键盘布局变化可能影响显示名称** → 保存 key code 与修饰键作为真实配置，显示名称只作为录制时的用户提示；在不同键盘布局上进行手动验证。
- **应用启动时历史配置可能注册失败** → 不删除用户配置，保留运行时错误并在高级页显示；托盘开关和其他 HUD 功能继续可用。
- **设置页即时保存与待配置状态存在差异** → 只有验证和注册成功后才更新 `@Published` 持久化字段，避免普通 `didSet` 直接保存半成品。

## Migration Plan

1. 新增的启用字段默认为 `false`，快捷键字段默认为 `nil`，无需迁移 `todos.json`。
2. 发布后首次启动保持现有无全局快捷键行为；用户必须主动进入高级页并完成配置。
3. 回滚到旧版本时，旧版本忽略新增 UserDefaults 键，不影响任务数据；应用退出后由系统清理当前进程的快捷键注册。
4. 验证覆盖首次启动、待配置、成功启用、关闭后恢复、注册失败回滚、系统快捷键提示和第三方冲突警告。
