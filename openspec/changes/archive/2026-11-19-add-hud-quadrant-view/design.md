# Design

## Context

`DesktopNotesBoardView` 使用 `TodoStore.hudProjection` 的列表结果，Todo 可能已经被 Doing 聚焦隐藏，超过上限的任务也已被截断。`WindowCoordinator` 管理一个面板，移动与缩放回调共用 `hudFrame`。交互模式、窗口位置与透明度已有各自的偏好。

## Goals / Non-Goals

Core 负责取数、排序和分类。App 负责选择视图和调整原有窗口。本次使用已有任务字段，范围为 macOS 桌面 HUD；Windows、CLI 和任务持久化格式不在本次变更内。

## Decisions

1. **先筛选、排序，再按视图投影。** 共用当前范围和排序逻辑，列表分支继续应用聚焦和上限，四象限分支直接对完整结果分组。若复用已截断的列表，四象限无法还原隐藏任务。以传入的日历和当前时间计算次日零点；监听日期变更和唤醒，重新计算今天新增和紧急程度。分类无需回写任务。
2. **只保存用户主动选择的交互视图。** 在 AppPreferences 增加一个 UserDefaults 偏好，缺省为列表。根据 HUD 模式和此偏好推导当前视图。菜单栏、快捷键、启动恢复走同一取值路径。指针回调仅调整透明度。
3. **沿用同一个 HUD 面板和任务行。** 交互模式提供原型中的两项选择器。四格按设计稿排列，以各自的滚动区域容纳任务。两种视图共享状态按钮、按任务 ID 的点击冷却、完整状态计数和文件变更刷新。原型的示例数据、主题和演示控件只用于对照。
4. **分别恢复列表和四象限的尺寸。** 保留现有列表窗口尺寸，首次展开参考原型宽度 720 pt。窗口切换尽量固定左上角，并限制在当前屏幕的可用区域。保留用户移动后的位置。缩放回调按当前视图保存尺寸，切换布局时避免把程序设置的四象限尺寸写入列表偏好。列表另存一个不含交互临时增高的基准高度：仅用户真实调高或内容适配时更新，仅移动/仅调宽/程序化显示与布局切换都按基准高度持久化，保证穿透↔交互往返与跨四象限不丢失紧凑高度。
5. **四象限收为列表自动贴边（交互手动与穿透两入口）。** 试用反馈四象限收起后仍停在屏幕内侧遮挡工作，故四象限收为列表的两个入口——交互模式手动点「单列」与切回穿透——都把列表水平收拢到当前显示器 visibleFrame 较近的左或右侧边：以收起前四象限窗口的左/右间距判断（已碰边算零），仅比较水平两边（`collapseSide`），顶/底再近也不参与以免水平位置滞留，平局确定优先左；水平轴贴所选边，垂直位置尽量保留并夹取，保持列表可见与已选尺寸。交互手动收起后仍可操作任务、显示工具栏并持久化视图为列表。主动展开四象限（列表→四象限）与交互列表/穿透列表往返不吸边，沿用固定左上角规则。收起后再次进入交互恢复四象限时还原收起前的四象限 frame（位置与尺寸），显示器变化时夹取；穿透态重启恢复收起后的列表位置。贴边与恢复均由 Core 纯几何函数（`HudFrameGeometry`）计算，便于无屏幕回归。无历史列表尺寸时收起先用默认高度贴边，随后内容适配确定最终高度后沿收起所选边重新对齐并夹取、保存最终 frame（`contentFittedListFrame`）；该临时贴边状态在布局切换、重新展开或用户移动/缩放时清除。列表窗口高度沿用 `max(基准, 模式最小值)`：基准取持久化列表尺寸，交互工具栏最小高度的临时增高由模式度量处理、不写回基准，仅用户真实调高或首次内容适配更新基准；首次内容适配的基准由 `firstFitBaseHeight` 选择：仅无历史初次测量、当前交互且实测恰为交互最小值（空列表含工具栏 184）时，持久化基准取穿透最小值 144（窗口仍显示 184 并贴边，同模式重启 184、随后穿透 144）；实测超过交互最小值（如 340）则存实测全高，同模式刷新与重启不丢高度。已有/用户主动设置的尺寸不走此路径，旧偏好（如 300）启动与往返保持原值。

## Risks / Trade-offs

- 旧版已有列表窗口位置和尺寸。升级时应直接沿用，再用新偏好保存四象限尺寸；缺少新增字段时默认列表。
- 两个尚未归档的变更分别描述 Doing 聚焦和紧凑列表。它们的列表条数、单列宽度和吸顶规则适用于列表。归档时逐条核对同名需求，避免覆盖本变更在四象限中的例外。
- 窗口收展后指针可能落在新的边界内外。按最终窗口区域重算穿透透明度，验证鼠标事件仍传给下方应用。
