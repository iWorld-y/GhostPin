# Design

## Context

[提案](proposal.md) 描述了使用任务拖动调整优先级和切换状态的需求。`DesktopNotesBoardView` 的单列与四象限共用任务行，圆形按钮通过 `AppState.advanceStatus` 推进状态。四象限按当前本地日期从 `important`、`urgent` 和 `dueAt` 推导。单列的 `HudProjection` 只返回筛选后的可见任务，但保留范围内的完整分区计数。

HUD 使用无边框 `NSPanel`，现有背景支持移动窗口。任务更新通过 `TodoStore` 和 `TaskStorage` 共用 `.todos.lock`。App 订阅内存更新，文件监听负责读取 CLI 的外部写入。

## Goals / Non-Goals

**Goals**

- 复用任务行和窗口内的拖动状态。两种视图各自定义落点和允许更新的字段。
- 在同一次存储事务内校验最新任务并提交。失败或取消时收起拖动提示，界面继续展示最近的有效快照。

**Non-Goals**

- 范围限于同一个 macOS HUD 内的单任务移动。跨窗口传输、批量拖动和手动排序不在本次范围。
- 任务状态继续由现有圆形按钮推进到 Done。拖动可以调整的状态只有 Todo 和 Doing。

## Decisions

### 在 HUD 内识别任务拖动

共用任务行只在交互模式显示手柄。优先用 SwiftUI `DragGesture` 把手柄位置转换到 HUD 坐标。视图在开始拖动时记录任务 ID 和起始分类，在板面显示预览，并标记指针下的落点。圆形按钮仍处理点击和键盘操作，标题栏仍用于移动窗口。

系统拖放提供原生预览，也支持跨视图和跨应用的数据传输。窗口内手势可以直接处理本功能所需的单面板落点，无需注册传输类型。若 Intel Mac 上的实测显示背景移动抢占手柄，在 AppKit 层明确划分手柄与窗口的拖动区域。关闭 HUD、切换模式或视图以及窗口失活时清除当前拖动。

### 保留自动排序并单独显示隐藏的目标

四象限以整格作为目标，空格同样接收。单列在拖动期间显示固定的 Todo 和 Doing 落点，落点不计入条数上限，也不改变窗口尺寸。只有已显示的任务卡片能开始拖动。结束后使用原有分区、排序、范围和 Doing 聚焦。移动成功后显示目标状态，尤其是在新状态的卡片因筛选被隐藏时。

始终显示空分区会改变静止时的列表布局。只让现有分区接收会使第一条 Todo 无法拖入 Doing，也会使开启 Doing 聚焦时无法把任务拖回 Todo。临时落点覆盖了两种情况。

### 在保存前检查当前任务

`AppState` 检查 HUD 模式、视图和显示范围是否仍与拖动开始时一致，并将操作交给 Core。Core 复用现有任务事务，在锁内按 ID 读取最新记录。四象限操作检查任务仍未完成、当前有效象限仍是起始象限，并以投放时的本地日期判断目标是否可达。单列操作检查当前状态仍是起始状态，目标为另一种未完成状态。两种操作都检查任务仍属于当前显示范围。若最新数据已变为同一目标或条件已失效，直接结束事务，不保存任务文档。

四象限按目标行写入 `important`，只有换列才写入 `urgent`。对因截止时间而紧急的任务，纵向移动保留原有手动紧迫标记。这样即使后来改期，任务仍会按改期后的有效紧迫程度分类。右列禁放条件复用现有的本地次日零点判断。直接清空截止时间会同时改变用户保存的日期，而始终把左列写成手动紧急会在改期后继续保留紧急标记。

单列直接选择目标状态，沿用未完成任务的完成时间处理。现有 `setStatus` 和 `update` 可处理 CLI 的通用请求，但无法拒绝拖动期间已经完成或移走的记录。为拖动增加受限入口，共享底层锁和保存逻辑。成功提交后发布真实快照，由现有投影更新画面。

## Risks / Trade-offs

- 手柄与窗口移动、滚动或状态按钮争用鼠标事件。使用独立手柄和最小拖动距离，并在 Intel Mac 上确认点按、拖动、滚动和窗口位置。
- 临近跨日、CLI 改期或修改状态时，拖动开始后的目标可能改变。投放时重新验证，并说明任务已变更或截止时间限制。
- 文件写入失败或新状态受筛选隐藏时，卡片可能未出现在目标区。分别提示保存失败和保存成功，按实际保存结果决定界面反馈。

## Migration Plan

继续使用任务存储 v3 和现有兼容读取。回退应用版本时，已经保存的字段仍按原格式读取。
