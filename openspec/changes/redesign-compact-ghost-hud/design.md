# Design

## Context

动机与产品范围见 `proposal.md`。设计来源为已通过设计工具读取的「GhostPin UI 重设计」，入口文件为 `ghostpin-hud-redesign.html`。

`DesktopNotesBoardView.swift` 同时包含面板与任务卡片；现有布局为 16 pt 面板内边距、10 pt 卡间距和 12 pt 卡片内边距。`WindowCoordinator` 以 360 × 460 pt 创建窗口，并恢复 `hudFrame`。任务集合与完整计数已经由 `TodoStore.hudProjection` 提供，状态点击冷却已由 `AppState.advanceStatus` 处理。上述数据与交互链路可以直接沿用。

当前还有 `hud-doing-focus-and-hover-ghost` 变更，其分流与隐身实现已进入当前代码，但部分人工验收仍未勾选。本次不得代替它补勾任务，也不得回退它的现有行为。

## Goals / Non-Goals

**Goals:**

- 将 HTML 草案转换为最低支持 macOS 14 的原生 SwiftUI 视图，沿用现有 AppKit 窗口协调和 Core 投影。
- 将草案缺少的组别标记纳入固定元信息列，并保留既有数据、偏好与状态转换契约。
- 让展示、布局测量和窗口编排各自保持明确职责。

**Non-Goals:**

- 不引入 WebView、外部 UI 依赖、存储迁移、新设置、录入 UI 或新的全局快捷键。
- 不移植原型的撤销、外围演示控件、示例任务、桌面壁纸或写死的快捷键。
- 不同步 Windows 样式，也不自动提交、发布或替换已安装的 App。

## Decisions

### 1. 继续使用原生视图和现有投影

面板通过零间距 `LazyVStack` 与 `Section` 组织任务，使用现有分区数组与完整计数。分区头启用吸顶；每行之间绘制细分隔线。滚动底部的淡出覆盖层不接收鼠标事件，只在内容确实溢出时显示。

头部计数取 `doingCount`、`todoCount`，底部实际渲染条数取两个数组的长度合计，总数取两个完整计数合计。这样 Doing 聚焦与条数上限继续保持现有语义，无需新增 Core 汇总逻辑。底部快捷键使用现有配置的 `displayName`，且只在已启用并成功注册时显示。

不嵌入 HTML。原生视图能继续使用系统材质、键盘焦点和现有窗口事件，也无需新增 HTML 与 Swift 的任务写入桥接。

### 2. 固定元信息列并保留组别

行栅格沿用草案的 15 pt 状态列、弹性文本列、84 pt 元信息列，列间距为 9 pt，行内边距为上 6 pt、左右 12 pt、下 7 pt。状态图形约 11 pt，命中区域至少 27 pt 高，并限制在状态列附近，避免侵入标题。

标题为 13 pt、最多两行，描述为 11 pt、最多一行。元信息列上方为「优先级、组别」，下方为截止日期，使用约 10 pt 字号。继续用当前字体测量三个汉字的宽度限制组名，显示截断不改变完整组名。没有描述或截止日期时不增加对应文本行。

将组别放到另一行会增加行高，也会偏离现有「组别在优先级右侧」的规格，因此两者继续放在元信息列顶部。

### 3. 使用系统材质与语义颜色

面板保留系统材质，移除面板和任务卡片的彩色渐变，整体圆角改为 14 pt。前景、次要文字、分隔线与悬停背景从系统语义颜色派生，自动适配浅深色。高优先级和逾期使用相同的红色语义，中、低优先级以灰度和字重区分。Doing 分区点与焦点提示使用系统控制色。

关闭按钮在穿透模式下隐藏并停用，但保留占位。窗口透明度及指针进入后的隐身仍由 `WindowCoordinator` 负责，视图不再叠乘原型中的固定 70% 透明度。系统减弱动态效果设置开启时减少新增的过渡动画。

### 4. 已保存尺寸优先，首次高度随内容确定

窗口默认宽度改为 380 pt，视图与窗口最小宽度统一为 320 pt，移除现有 280/300 pt 的强制最小高度。视图层负责测量自然内容高度，正文最大高度为 396 pt；空态正文以 80 pt 参与初始布局。

窗口协调器只在本次首次创建窗口且没有保存尺寸时，根据视图给出的内容高度调整一次窗口。已有 `hudFrame` 继续优先，用户之后手动调整的尺寸也照常保存。列表刷新不反复改写窗口尺寸，从而避免任务完成时窗口位置跳动或覆盖用户的几何偏好。

这与原型每次随内容收缩的行为有所区别，原因是正式产品已经承诺恢复用户调整的窗口尺寸。正文在已保存的大窗口中保持靠上布局。

### 5. 保留任务写入入口与演示边界

行按钮继续调用 `AppState.advanceStatus`，不创建新的状态修改路径。Todo、Doing 的图形变化只反映当前状态；完成后从 HUD 消失，不保留撤销状态或计时器。

原型外围的模式、范围、外观、空态切换控件不进入产品界面。已有菜单栏和设置页仍负责这些偏好。空态文案仅提供提示，示例应包含必填组别，例如 `ghostpin-cli add "写周报" --group 默认`。

## Risks / Trade-offs

- 长标题、长组名和日期会争用窄窗口空间。通过固定 84 pt 列、文本截断和 320 pt 原生截图检查确认互不重叠。
- 系统材质在不同壁纸和浅深色外观下对比度不同。使用语义颜色，并在原生窗口中检查，而不把 HTML 截图视为原生验收结果。
- 行高缩小后状态按钮可能难点。保留至少 27 pt 高的命中区域，检查鼠标与键盘触发，以及 500 ms 冷却行为。
- SwiftUI 滚动视图的自然高度测量可能影响首次窗口尺寸。使用兼容 macOS 14 的布局测量方式；只在无保存尺寸的首次创建时采用测量值。
- Windows 样式与 macOS 将出现差异。本次明确仅改 macOS，不将跨平台视觉一致性描述为已完成。

## Migration Plan

不迁移数据和偏好。已有窗口尺寸与设置继续读取原键值，后续只有用户调整窗口时按现有规则保存几何。

回退时恢复本次 HUD 视图与窗口默认尺寸改动即可；无需修改任务文件、撤回任务状态或回退存储版本。
