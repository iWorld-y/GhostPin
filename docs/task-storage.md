# 任务存储与升级

## 文档与编号

macOS 任务文件仍为 `~/Library/Application Support/GhostPin/todos.json`，Windows 为 `%LOCALAPPDATA%\GhostPin\todos.json`。顶层文档示例：

```json
{
  "schemaVersion": 2,
  "nextID": 10001,
  "items": [
    {
      "id": 10000,
      "group": "默认",
      "title": "整理周报",
      "createdAt": "2026-10-19T09:00:00+08:00",
      "status": "todo",
      "priority": "medium"
    }
  ]
}
```

`id` 和 `nextID` 是 JSON 整数。各组共用一个从 `10000` 开始的序列，任务删除、清空、完成或换组都不回退计数器。为保证 Windows JSON 数字精确往返，任务 ID 最大为 `9007199254740990`，下一编号最多为 `9007199254740991`；用尽时拒绝新增，不循环使用旧编号。

每条任务必须有非空组名。输入先去掉首尾空白，再按完整名称区分大小写地匹配；新增必须显式指定组别。内置组名为 `默认`。HUD 的三汉字文本宽度上限仅作用于显示，完整组名保存在任务文件和 CLI 输出中。

存储校验版本、唯一 ID、组别及下一编号。未知版本、缺少组别、重复 ID、空组别、损坏 JSON 和无效计数器均拒绝读写，保留原文件及 App 最后一次有效快照，不自动重置为空库。`list --json` 继续输出任务数组，不输出文档封装。

## 首次升级

升级前退出旧 App 和 CLI，同时更新应用及随包 CLI。旧程序无法读取新文档，也不遵守本次写锁约定。开发验证只使用临时数据，不替用户升级真实待办。

首次成功访问旧 UUID 数组时，在固定 `.todos.lock` 保护下执行以下过程：

1. 读取并校验原数组，按创建时间升序排序；时间相同时，按 UUID 小写字符串排序。
2. 从 `10000` 起为全部任务编号，包含已完成任务；组别统一设为 `默认`，保留既有业务字段及缺省字段兼容行为。
3. 将原始字节写入同目录的 `todos.v1.backup.json`。相同备份可以复用，不同内容的已有备份会导致失败，绝不覆盖。
4. 将任务与下一编号一起原子替换为新文档，成功后才发布内存快照。备份或提交失败时保留原文件，重试仍得到同一映射。

普通查询可以触发迁移。帮助、参数错误和不存在的目标任务不会提交迁移或创建备份。成功写操作可将格式升级与业务修改合并为一次提交，原始备份仍为修改前的数组。任务文件不存在且无旧数据时，普通查询返回空数组，不创建 `todos.json`。

GhostPin 文件优先于 TodoPin 文件。GhostPin 文件不存在时，macOS 在目标目录锁内读取旧 `TodoPin/todos.json`，直接生成新文档和原始备份；旧源文件始终不变。GhostPin 文件已存在但损坏时会报错，不退回旧目录覆盖。

## 并发写入

新增、字段更新、换组、状态推进、删除、提醒记录和迁移都在固定锁文件保护下重新读取最新文档。调用方只提交需要修改的字段，不能把旧任务集合整体写回。任务与计数器一次提交，成功前不发布新快照；目标已被删除时不能重建该任务。

macOS 使用 `flock`，Windows 使用 Rust 标准库文件锁（构建要求 Rust 1.89 或更新版本）。锁文件不随任务文件原子替换而更换，进程退出时操作系统释放锁。请保留 `.todos.lock`，不要在程序运行时删除或替换它。

Windows 同步支持新文档、旧数组迁移、原始备份和锁内状态推进，保留组别及下一编号。不提供 Windows 任务新增 CLI、分组管理 UI 或跨机器同步。本次没有改变两端既有的 HUD 聚焦差异。

## 对照旧 UUID

旧 UUID 不保留为操作别名。需要核对历史引用时，读取原始备份，按上述创建时间与 UUID 顺序排序，首条对应 `10000`，之后依次加一，再以新 CLI 查询整数 ID。

共享夹具 `windows-native/tests/fixtures/tasks-groups-legacy.json` 的映射为：UUID 尾号 `001` 对应 `10000`，同一创建时间的 `003` 对应 `10001`，创建较晚的 `002` 对应 `10002`。对应新文档在 `tasks-groups-v2.json`，Swift 和 Rust 检查共用这两个文件。

## 回退边界与隔离验证

回退前先退出新 App 和 CLI，把当前新格式文件另外保存，再核对 `todos.v1.backup.json`。备份只包含迁移时的数据，不包含升级后的新增、删除、字段修改或状态推进。先处理这些差异，再由用户选择恢复备份及匹配的旧程序；没有自动降级功能，不要让旧程序直接写新文档。

可在临时目录中演练，不接触真实数据：

```bash
make build
make test
python3 script/check_cli.py
make verify
```

CLI 集成检查会复制旧夹具到临时目录，执行迁移、组别查询与修改、并发新增、删除和继续编号，并逐字节核对失败命令的保护行为。若需演练恢复，在该临时目录中停止进程、另存新文档，再将原始备份复制为 `todos.json`；恢复出的内容必须与旧夹具逐字节相同，之后只能用匹配的旧程序读取，或重新触发新版本迁移。

开发构建通过 `GHOSTPIN_TEST_SUPPORT_ROOT` 隔离 App 与 CLI 的任务目录，Release 不提供该环境入口。`make verify` 自动创建临时目录，并清理自己启动的验证进程。正式待办仍只能通过已安装应用内 CLI 操作，不使用开发二进制验证真实数据。
